# Roadmap / 已知不足

按「会不会咬人」排序，不按工作量。前三条直接影响能不能跑通，后面是能力边界。

## 现在就有的洞

### 1. 前台点击依赖一个未收录的模块

`batch_course.py` / `foreground_play.py` 在焦点处理里 `from browser_focus import capture_focus / restore_focus`。该模块**未随仓库提供**（原版里耦合了本机窗口几何与私有路径），因此：

- `--allow-foreground-click` 路径会 `ImportError`；
- 不使用前台点击（播放器能自动播）时不受影响。

要修：按 `capture_focus() -> {window_id, ...}` / `restore_focus(prior, owned, expected_url=...)` 的现有调用契约补一个实现，或在调用处降级为「不做焦点快照」。

### 2. `resume_stitch.py` 未收录

`docs/quickstart.md` 里出现的分段拼接脚本未进本仓库。当前录制是一课一文件、不切段，所以不影响主流程；只有需要「断点续录拼接」时才需要它。

### 3. 验收只判「能解码 + 有声音」

`completed` 的三个条件（decode / audio / volumedetect）拦得住空文件、坏封装、静音轨，但拦不住：

- 画面停在某一帧（有声音、能解码，内容没动）—— PlaybackAudit 能拦一部分，但它看的是播放器 `currentTime`，不是像素；
- 说话人身份不对（录错课但标题对）；
- 音画不同步。

要修：加抽帧哈希/感知 diff，或把 `currentTime` 与已录时长做闭环对账。

## 能力边界

### 4. 前台点击依赖窗口几何

`foreground_play.py` 用窗口几何算播放按钮坐标。换浏览器版本、换主题、改缩放、加侧边栏都可能点空。当前的兜底是焦点重试 + 失败保留证据，但没有基于 DOM 的点击路径。

### 5. 时间窗写死 `22:00–07:00`

`recording_schedule.py` 的窗口起止是常量，时区可配（`RECORDER_TZ` 或策略里的 `timezone`），但起止时间没做成配置项，也没接 cron。要做「白天某几小时也允许」，得改代码。

### 6. 抓取器不在仓库

刻意如此。队列里的每个 URL 都是外部抓取器认定的「存在且完整」（`inventory_complete` 校验），工具不自己发现内容。代价：换平台就得自己写抓取器。

### 7. 约 30 个 `test_*.py` 未纳入

原版有覆盖调度、录制、焦点、时间窗的测试，但大量引用真实路径与真实 URL，脱敏成本高于收益。当前仓库只有语法级保证（`py_compile`）+ 手工 smoke 流程。要补测试请按现有接口重写，别指望能直接搬。

### 8. 运行时零模型依赖，是刻意取舍

工具不调用任何 API、不做 AI 判断，判据全部是 DOM 状态 + `ffmpeg` + 系统会话信息。代价是「判断失败类型、决定重试还是隔离」这类事必须由人或外部 agent 做。目前不打算把判断塞进录制进程内：录制的正确性不该依赖一个概率模型，而且失败归因需要的上下文（历史 attempts、环境状态）比录制本身复杂得多。

### 9. 音频污染没有自动检测

`-A` 抓的是系统最终混音，其他应用的声音会混进成品。现在的防线只有两个：事后 `volumedetect`（只能发现「静音/过响」，发现不了「混进了别的音乐」）和人守规矩。要修：录制期间采样系统音频做「与课程无关的音源检测」，或至少在 sidecar 里记录当时的输出设备与前台应用变化。

## 顺手能做的

- `--status` 输出做成机器可读（`--json`），便于接监控
- sidecar 版本号 + schema 校验
- 断点恢复前把「上次异常退出的现场」自动归档成单独目录
- 失败归类打分（前台被抢 / 播放卡死 / 磁盘不足 / 权限），现在靠读 sidecar 人工判断
